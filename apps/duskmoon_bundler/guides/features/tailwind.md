# Tailwind CSS

DuskmoonBundler compiles Tailwind CSS v4 natively at runtime. [Oxide](https://hex.pm/packages/duskmoon_oxide) scans source files in parallel for candidate class names, then the Tailwind compiler (running in [QuickBEAM](https://hex.pm/packages/duskmoon_quickbeam)) generates CSS. [LightningCSS](https://hex.pm/packages/duskmoon_vize) handles minification.

The Tailwind compiler is installed into the npm_ex cache on first use — no manual setup required.

## Configuration

```elixir
config :duskmoon_bundler,
  tailwind: [
    css: "assets/css/app.css",
    sources: [
      %{base: "lib/", pattern: "**/*.{ex,heex}"},
      %{base: "assets/", pattern: "**/*.{vue,ts,tsx}"}
    ]
  ]
```

- `css` — path to your Tailwind input CSS file (with `@import "tailwindcss"`)
- `sources` — list of `%{base, pattern}` maps defining where to scan for class names

## CSS Source Declarations

CSS `@source` paths are scanned alongside configured source patterns, including
explicit paths into gitignored dependencies:

```css
/* assets/css/app.css */
@import "tailwindcss" source(none);
@source "../../lib";
@source "../../deps/my_component/assets/js";
```

Paths are relative to the stylesheet declaring them, including declarations in
imported stylesheets. Negated declarations (`@source not`), inline candidates,
and explicit `source("path")` roots are supported. An empty `sources: []` list
allows CSS-only source configuration. For programmatic builds, set `css_base`
to the input stylesheet's directory.

Incremental rebuilds retain the CSS input, its base directory and the combined
scanner. Watcher subscriptions use configured `tailwind.sources` and
`server.watch_dirs`; include external directories there to receive change events.

## Plugins and Config Files

Tailwind `@plugin` and `@config` directives are resolved and bundled automatically:

```css
@plugin "@tailwindcss/typography";
@plugin "./my-plugin.js";
@config "./tailwind.config.js";
```

npm packages are resolved from `node_modules`. Local files are resolved relative to the CSS input file. The full `require()` graph is bundled so the Tailwind runtime evaluates self-contained modules.

## Incremental Rebuilds

In dev mode, only changed files are re-scanned. If a `.heex` template adds new Tailwind classes, only those new candidates trigger a CSS rebuild — the browser gets a style-only update without a page reload.

Development watchers use the configured `tailwind.sources` patterns, including dependency directories outside the asset root and `server.watch_dirs`. Each profile owns its scanner and compiler runtime, so starting or rebuilding another profile does not replace its candidates or consume its updates. A shared source change updates every affected profile's stylesheet.

Editing a Tailwind input stylesheet also regenerates CSS when no new class candidates were added, so changes to themes and custom utilities reach the browser through style HMR.

## Production Build

```bash
mix duskmoon_bundler.build --tailwind
```

The `assets.build` and `assets.deploy` aliases generated by the installer include `--tailwind` automatically.

## Programmatic API

```elixir
{:ok, css} = DuskmoonBundler.Tailwind.build(
  sources: [
    %{base: "lib/", pattern: "**/*.{ex,heex}"},
    %{base: "assets/", pattern: "**/*.{vue,ts,tsx}"}
  ],
  css: File.read!("assets/css/app.css"),
  minify: true
)
```
